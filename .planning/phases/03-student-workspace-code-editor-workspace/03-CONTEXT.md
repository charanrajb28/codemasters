# Phase 3: Student Workspace & Code Editor Workspace - Context

**Gathered:** 2026-09-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Build the Student Problem Catalog (`/problems`), interactive Split-Pane Code Editor Workspace (`/problems/[slug]`) with Monaco editor, multi-language support (Python, C++, Java, JavaScript), sample test case runner panel with custom input, submission queueing pipeline UI, and submission history log with code inspection.

</domain>

<decisions>
## Implementation Decisions

### Problem Catalog & Filter Interface (STUDENT-01)
- **D-01:** **Structured Table Layout**: Problem catalog at `/problems` rendered as a clean structured table with search bar and filter pills at top. Columns: Solved Status indicator, Problem Title (link to workspace), Difficulty badge (`Easy` green, `Medium` yellow, `Hard` red), Category Tags, and Acceptance Rate %.
- **D-02:** **Multi-Criteria Filtering**: Filter bar supports search query input, Difficulty filter dropdown, Category/Tag selector, and Solved Status filter (`All`, `Unsolved`, `Solved`, `Attempted`).

### Split-Pane Code Workspace & Monaco Editor (STUDENT-02, STUDENT-03)
- **D-03:** **Full Split View Layout**: Left pane contains tabs for `[Description, Submissions, Editorial]`. Right pane features Top Action Bar with Language dropdown (Python, C++, Java, JavaScript), Reset Code button, and Monaco Code Editor (`vs-dark` theme), with a collapsible bottom drawer for `[Test Cases, Test Results]`.
- **D-04:** **Starter Code Templates & Draft Persistence**: Default starter templates populated per language (e.g. `class Solution:` for Python, `int main()` / `class Solution` for C++/Java/JS). User code edits auto-saved to browser `localStorage` per problem slug and language.

### Sample Test Runner & Output Console (STUDENT-04)
- **D-05:** **Interactive Test Case Tabs**: Output drawer features tabbed navigation for sample test cases (`Case 1`, `Case 2`, `+ Custom Input`). Allows students to view/edit test case inputs and expected outputs.
- **D-06:** **Rich Result Diagnostics**: Running code displays per-test-case status badges (`Passed ✓` green, `Failed ✕` red), actual output vs expected output diff comparison, stdout/stderr execution log box, and execution runtime (ms).

### Submission Pipeline UI & History Log (STUDENT-05, STUDENT-06)
- **D-07:** **Live Status Transition & Verdict Card**: Clicking "Submit" updates button state dynamically (`Queued...` ➔ `Running...`), then displays a prominent Verdict Banner (`Accepted`, `Wrong Answer`, `Time Limit Exceeded`, `Memory Limit Exceeded`, `Runtime Error`, `Compilation Error`) along with test cases passed counter (e.g., `15 / 15 Test Cases Passed`).
- **D-08:** **Submission History & Code Viewer**: "Submissions" tab in left pane lists historical submission attempts with colored verdict badges, language, execution time (ms), memory footprint (MB), and timestamp. Clicking any historical attempt opens a modal showcasing the exact submitted code.

### Claude's Discretion
- Monaco editor keybindings, font size settings, and minimap toggle.
- Animation keyframes for submission status transitions.
- Default starter code function signatures for common DSA topics.

</decisions>
